# Telegram-бот для подготовки к ЕГЭ (Задание 5: паронимы)

Бот помогает отработать задание 5 ЕГЭ по русскому языку: лексические нормы и паронимы.
Пользователь выбирает слово из трёх вариантов; следующее задание открывается только
после верного ответа.

## Возможности

- **📚 Тренировка** — 365 заданий, варианты ответа перемешиваются на лету.
  Неверный ответ не закрывает задание, а повышает «поколение» клавиатуры, поэтому
  очередь кликов по старым кнопкам отбрасывается (защита от перебора).
- **📊 Статистика** — верные ответы, всего ответов, точность, текущая и лучшая серия.
- **🏆 Таблица лидеров** — топ-20 по верным ответам. Колонки выровнены в
  моноширинном блоке, поэтому цифры стоят ровно друг под другом:

  ```
   1. Пархаева           — 1079 | 🔗   80
   2. Александр (◕‿◕✿)   —  202 | 🔗   10
   3. Cageyserg          —   96 | 🔗   15
  ```

  Слева — всего верных ответов, после 🔗 — лучшая серия подряд. Длинные имена
  обрезаются до 18 клеток (с учётом ширины кириллицы и эмодзи), ранги
  выровнены по правому краю.
- **Команды**: `/start`, `/help`, `/top`, `/count`.

## Стек

- Python 3.11+
- [pyTelegramBotAPI](https://github.com/eternnoir/pyTelegramBotAPI) 4.37.1 (telebot)
- Flask 3.1 + gunicorn — webhook-режим для Render
- MongoDB — единственное хранилище статистики
- pytest, ruff — тесты и линтер

## Структура проекта

```
ege-paronym-bot/
├── main.py                  # long polling (локально / VPS)
├── web_app.py               # webhook-режим (Render, Flask + gunicorn)
├── config.py                # конфигурация из переменных окружения
├── core/

├── handlers/
│   ├── start.py             # команды /start, /help, /top, /count
│   ├── callbacks.py         # меню, тренировка, статистика, лидерборд
│   ├── state.py             # состояние тренировки (с ограничением размера)
│   └── text_handler.py      # подсказка «отвечайте кнопками»
├── keyboards/
│   └── inline.py            # инлайн-клавиатуры
├── utils/
│   ├── data_manager.py      # задания + операции статистики
│   ├── mongo_database.py    # MongoDB: единственное хранилище статистики
│   └── formatting.py        # экранирование Markdown и подписи пользователей
├── data/
│   └── paronyms.json        # задания
├── tests/                   # pytest: 103 теста, покрытие ~92%
└── .github/workflows/ci.yml # линтер + тесты на 3.11 и 3.12
```

Хендлеры регистрируются ровно один раз — в `core/bot_core.py::register_handlers`.
И `main.py`, и `web_app.py` используют эту функцию, так что набор обработчиков
не может разъехаться между режимами запуска.

## Быстрый старт

```bash
git clone https://github.com/Cageyserg/ege-paronym-bot.git
cd ege-paronym-bot
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env      # вписать BOT_TOKEN и MONGODB_URI
python main.py
```

`MONGODB_URI` обязателен: без него бот не запустится. Статистика (ник, username,
число верных ответов, лучшая серия) хранится только в MongoDB.

### Переменные окружения

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен от @BotFather (обязателен) |
| `WEBHOOK_URL` | Публичный адрес приложения (webhook-режим) |
| `WEBHOOK_SECRET` | Секрет для проверки заголовка `X-Telegram-Bot-Api-Secret-Token` |
| `ADMIN_TOKEN` | Токен для `POST /set-webhook` и `/delete-webhook` |
| `MONGODB_URI` | Строка подключения MongoDB (обязательна) |
| `MONGODB_DB` | Имя базы в кластере (по умолчанию `ege_paronym_bot`) |

## Деплой на Render

`render.yaml` описывает сервис, `/health` используется как health check.

```bash
gunicorn web_app:app --workers 1 --threads 8 --bind 0.0.0.0:$PORT
```

- Статистика в MongoDB, поэтому воркеры независимы: каждый ответ пишется
  атомарным апдейтом, кэша в памяти нет.

> **Start Command на Render.** Если сервис создан вручную (а не из
> `render.yaml`), команда запуска берётся из дашборда и перекрывает
> `render.yaml`. Правильное значение:
>
> ```
> gunicorn web_app:app --workers 1 --threads 8 --bind 0.0.0.0:$PORT
> ```
>
> Старое значение `gunicorn render_main:app` тоже работает: `render_main.py`
> оставлен как алиас на `web_app.app`, чтобы не ломать уже настроенный сервис.
>
> **Версия Python.** Render берёт её из переменной `PYTHON_VERSION` или файла
> `.python-version` (сейчас зафиксирован 3.11.9). Если в дашборде задана
> `PYTHON_VERSION`, она имеет приоритет над файлом.
- После первого деплоя установите webhook:
  ```bash
  curl -X POST -H "X-Admin-Token: $ADMIN_TOKEN" https://<app>.onrender.com/set-webhook
  ```
- Без `ADMIN_TOKEN` маршруты `/set-webhook` и `/delete-webhook` отвечают 403 —
  переставить webhook посторонний не сможет.
- При заданном `WEBHOOK_SECRET` запросы без верного заголовка отклоняются (403).

## Как добавить задания

Все задания лежат в `data/paronyms.json` — массив объектов:

```json
{
  "id": 389,
  "task": "Он был _____ человеком и всегда держал слово.",
  "options": ["памятным", "памятливым", "памятуя"],
  "correct_answer": "памятливым",
  "explanation": "«памятливый» — обладающий хорошей памятью."
}
```

Правила:

1. `id` — уникальный и не повторяет существующие.
2. `options` — не менее двух вариантов, все разные.
3. `correct_answer` — обязательно входит в `options`.
4. `explanation` — пояснение, показывается после верного ответа.
5. Пропуск в предложении обозначается `________`.

При старте файл читается один раз; некорректные записи (без вариантов или без
ответа) пропускаются с записью в лог. После правки файла процесс нужно перезапустить.

## Хранение статистики

Единственное хранилище — MongoDB, коллекция `user_stats`. На пользователя один
документ:

```json
{
  "user_id": 123456789,
  "username": "nick",
  "firstname": "Иван",
  "correct_answers": 12,
  "total_answers": 15,
  "streak": 3,
  "max_streak": 7
}
```

- `user_id` — уникальный индекс.
- Каждый ответ пишется сразу, атомарным апдейтом с агрегационным пайплайном:
  `correct_answers`/`total_answers` инкрементируются, `streak` растёт или
  сбрасывается в 0, `max_streak` обновляется через `$max`.
- Никакого кэша в памяти и никакого второго хранилища нет, поэтому данные
  одинаковы для всех процессов и переживают рестарт.
